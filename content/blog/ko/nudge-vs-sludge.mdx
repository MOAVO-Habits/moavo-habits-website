# 넛지 vs 슬러지(Sludge): 구독 해지 버튼은 왜 늘 찾기 어려울까?

**가입은 버튼 한 번이면 됐는데, 해지하려니 메뉴를 몇 번이나 뒤져야 했던 적 있으신가요?**

가입 버튼은 화면 한가운데 큼직하게 있었습니다. 그런데 해지 버튼은 설정 안의 설정, 그 안의 '계정 관리' 맨 아래에 작은 글씨로 숨어 있습니다. 겨우 찾아 누르면 그 다음에 "정말 떠나시겠어요?", "지금 해지하면 혜택이 사라집니다"와 같은  문구가 몇 번씩 이어지게 되면서 상당히 불편함을 겪게 됩니다.&#x20;

결국 사용자는 이 과정에서  "다음에 하지 뭐" 하고 창을 닫습니다.&#x20;

그리고 다음 달에도 결제는 그대로 됩니다.



지난 글에서 넛지를 이야기했습니다. 선택지는 그대로 두고 환경을 살짝 바꿔서 행동을 이끄는 방법이었죠.

그런데 같은 방법을 **반대 방향**으로 쓰면 어떻게 될까요?

## 1. 슬러지(Sludge)란 무엇인가

《넛지》를 쓴 리처드 탈러는 2018년 과학 저널 《사이언스》에 짧은 글을 하나 실었습니다. 제목은 \*\*"넛지는 하되, 슬러지는 하지 마라(Nudge, not sludge)"\*\*였습니다.\[1]

슬러지(sludge)는 원래 '진흙', '찌꺼기'라는 뜻입니다. 행동과학에서는 **사람이 자기에게 이로운 일을 하지 못하도록 일부러 번거롭게 만드는 장치**를 말합니다.

쉽게 말하면 이렇습니다.

* **넛지**: 하면 좋은 일을 **쉽게** 만든다
* **슬러지**: 하면 좋은 일을 **어렵게** 만든다

넛지의 공동 저자 캐스 선스타인은 아예 이 주제로 《슬러지》라는 책을 따로 썼습니다. 서류, 대기 시간, 복잡한 절차처럼 사람을 지치게 해서 결국 포기하게 만드는 '마찰'이 우리 삶 곳곳에 있다는 이야기입니다.\[2]

## 2. 넛지와 슬러지, 이렇게 다르다

같은 '설계'인데 방향이 다릅니다.

| 상황       | 넛지 (좋은 설계)                | 슬러지 (나쁜 설계)           |
| -------- | ------------------------- | --------------------- |
| 구독 서비스   | 가입만큼 해지도 쉽게               | 가입은 한 번에, 해지는 메뉴 깊숙이  |
| 무료 체험    | 유료 전환 전에 미리 알림            | 알림 없이 자동 결제           |
| 회원 탈퇴    | 앱 안에서 바로 탈퇴               | 고객센터에 전화해야만 탈퇴        |
| 환급·보상 신청 | 필요한 서류를 최소로               | 서류를 여러 장 요구해 포기하게 만들기 |
| 노후 저축    | 회사 연금에 자동 가입, 원하면 빠질 수 있게 | 가입하려면 서류를 따로 내야 함     |

마지막 줄은 《넛지》에도 나오는 가장 유명한 넛지 사례입니다. 미국의 한 회사가 퇴직연금을 '원하면 가입'에서 '기본은 가입, 원하면 탈퇴'로 바꾸자 가입률이 크게 올랐습니다. 선택지는 똑같은데, **기본값**만 바꾼 겁니다.\[3]

## 3. 좋은 넛지와 나쁜 넛지를 가르는 질문 하나

둘을 어떻게 구분할까요? 저는 이 질문 하나면 충분하다고 생각합니다.

**"이 설계는 누구에게 이로운가?"**

사람이 원래 하고 싶었던 일, 하면 자기에게 좋은 일을 쉽게 만들어주면 넛지입니다. 반대로 회사에는 이롭지만 사람은 손해를 보는 쪽으로 몰아가면 슬러지입니다.

이 질문을 하고 나니, 지난 글에서 이야기한 우리 빵집이 다시 떠올랐습니다.

식빵을 안쪽에 두면, 손님은 안쪽까지 걸어오면서 다른 빵들을 보게 됩니다. 이건 넛지일까요, 슬러지일까요?

솔직히 말하면 경계에 있다고 생각합니다. 손님이 맛있어 보이는 빵을 하나 더 발견하고 기분 좋게 사 간다면 손님에게도 나쁘지 않습니다. 하지만 식빵 하나 사러 온 바쁜 손님이 원하는 빵을 못 찾아서 매장을 헤매야 한다면, 그건 가게 편의만 생각한 설계입니다.

그래서 저는 기준을 이렇게 잡게 됐습니다. **찾는 건 쉽게, 구경은 자유롭게.** 손님이 원하는 걸 빨리 찾을 수 있으면서, 둘러보고 싶은 사람은 둘러볼 수 있게요.

## 4. 앱을 만드는 사람으로서 스스로에게 묻는 것

앱을 만들다 보면 이 유혹이 훨씬 커집니다.

사용자가 앱을 더 오래, 더 자주 쓰게 만드는 방법은 많습니다. 알림을 더 자주 보내고, 연속 기록이 끊기면 아쉬움을 크게 느끼게 하고, 해지 버튼을 조금 더 깊이 숨기면 숫자는 좋아질 수 있습니다.

그런데 그건 사용자가 원해서 머무는 게 아니라, 빠져나가기 어려워서 머무는 겁니다.

모아보해빗을 만들면서 저도 이 질문을 계속 붙잡고 있습니다.

* **알림**: 사용자가 정한 시간에, 사용자가 정한 습관만 알려주고 있나?
* **연속 기록**: 점이 쌓이는 게 동기가 되나, 끊겼을 때 죄책감만 남기나?
* **유료 전환**: 무료와 유료의 차이를 정직하게 보여주고 있나?

정답을 다 찾은 건 아닙니다. 하지만 "사용자가 원래 하려던 일을 돕고 있는가?"라는 질문을 계속 던지는 것만으로도, 적어도 슬러지 쪽으로 미끄러지지는 않을 수 있다고 생각합니다.

## 5. 내 습관에는 넛지와 슬러지를 거꾸로 써보세요

여기서 재미있는 점이 하나 있습니다. 슬러지는 나쁜 설계지만, **내가 직접 쓰면 좋은 도구가 됩니다.**

하고 싶은 습관에는 넛지를 넣어 쉽게 만들고, 끊고 싶은 습관에는 일부러 슬러지를 넣어 번거롭게 만드는 겁니다. 제임스 클리어도 《아토믹 해빗》에서 좋은 습관은 쉽게, 나쁜 습관은 어렵게 만들라고 말합니다.

| 목표           | 넣어볼 것     | 예시                        |
| ------------ | --------- | ------------------------- |
| 아침운동 하기      | 넛지 (쉽게)   | 전날 밤 운동복과 운동화를 침대 옆에 꺼내두기 |
| 저녁에 책 읽기     | 넛지 (쉽게)   | 읽을 책을 식탁 위에 펼쳐두기          |
| 자기 전 휴대폰 줄이기 | 슬러지 (어렵게) | 휴대폰을 침실 밖에서 충전하기          |
| 쇼핑앱 충동구매 줄이기 | 슬러지 (어렵게) | 간편결제에 저장된 카드 지우기          |
| 야식 줄이기       | 슬러지 (어렵게) | 과자를 눈에 안 띄는 높은 선반에 두기     |

하나만 골라서 며칠 해보세요. 그리고 짧게 남겨보세요.

***"휴대폰을 거실에서 충전했더니, 침대에서 습관적으로 집어 드는 일이 없었다."***

***"결제할 때마다 카드 번호를 입력하려니 귀찮아서, 장바구니에 담아만 두고 다음 날 보니 필요 없는 물건이었다."***

이런 기록이 쌓이면, 어떤 넛지와 슬러지가 내게 맞는지 보입니다.

## 6. 설계를 알아보는 사람이 되면

넛지와 슬러지를 알고 나면, 일상이 조금 다르게 보입니다.

마트 동선, 앱의 버튼 위치, 무료 체험 화면, 해지 메뉴. 그 앞에서 한 번쯤 이렇게 물어보게 됩니다.

**"이 설계는 나를 돕고 있나, 나를 붙잡고 있나?"**

그리고 그 질문을 내 생활에도 거꾸로 써볼 수 있습니다. 나를 돕는 넛지는 늘리고, 나를 붙잡는 슬러지는 걷어내고, 끊고 싶은 습관에는 내가 직접 슬러지를 깔아두는 겁니다.
